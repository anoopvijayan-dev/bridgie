# copilot adapter gotchas
- Flags verified against GitHub Copilot CLI 1.0.107: `-p` (non-interactive), `-s` (response only), `--no-ask-user`, `--model`, `--reasoning-effort none|minimal|low|medium|high|xhigh|max`, `--allow-tool` / `--deny-tool` (deny always wins), `--add-dir`.
- Token usage: `--usage-output-file <file>` (in Copilot CLI 1.0.117's help; written for `-p` runs too, also when the run fails before reaching a model). Its top level is totals (`totalPremiumRequestCost`, `totalNanoAiu`, `totalApiDurationMs`, ...), `modelMetrics` keyed by model, `agentMetrics` keyed by agent (main and each subagent) and `providerModelMetrics`. The adapter sums `modelMetrics.*.usage.{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}` only, so subagent tokens are not counted twice, and takes `inputTokens` to include cache reads and writes. UNVERIFIED: the per-model `usage` field names and that inclusion; seen so far only from a run that never reached a model (`modelMetrics: {}`). Check one signed-in run's file and record it here.
- `-p` takes the prompt text, so the adapter passes a short instruction to read the prompt file (Windows command-line limit).
- Vendor is derived from `--model` (claude/opus/sonnet → anthropic, gpt → openai, gemini → google). With `default` the vendor is `copilot-default`, which never matches another adapter, so set an explicit model when cross-family matters.
- Model names are Copilot's (check `copilot --help` / `/model`), e.g. `claude-opus-5.5`; they are not Anthropic API ids.
